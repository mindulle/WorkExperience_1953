## 수집 시 입력 항목 (팀원이 채우는 것)

리뷰 페이지를 보면서 바로 옮겨 적을 수 있는 항목만입니다.

| 컬럼 | 설명 |
|---|---|
| `branch` | 위 공식 지점명 6개 중 하나 |
| `channel` | 수집 채널 (예: GOOGLE, CATCHTABLE, NAVER, BAEMIN) |
| `reviewer` | 리뷰어 닉네임/표시명 (실명이 아닌 플랫폼 닉네임 그대로) |
| `rating` | 별점 |
| `review_date_raw` | 화면에 보이는 날짜 그대로 (상대 날짜 "3주 전"도 그대로 두면 됨 — 정규화는 후처리에서 처리) |
| `review_text` | 리뷰 본문. **가능하면 원문 언어로.** 자동번역본만 보인다면 그렇다고 메모에 남겨주세요 |

## 후처리 파생 항목 (병합 파이프라인이 자동 생성 — 수집 시 신경 쓰지 않아도 됨)

`review_id`, `source_persons`(출처 인원), `approx_ym`(날짜 정규화, 이슈 #68), `sentiment`/`positive_keywords`/`negative_keywords`/`mentioned_menu`(감성·키워드 분석, 이슈 #67), `duplicate` 관련 필드

## 감성 판정 기준 (이슈 #67)

`sentiment_final` 컬럼 값은 아래 6개 중 하나입니다.

| 값 | 의미 |
|---|---|
| 긍정 / 부정 / 중립 | 기본 3분류. `intensity`(강/약)로 세기 구분 |
| 혼합 | 서로 다른 평가대상(예: 맛 vs 매장환경/위생)이 뚜렷이 갈릴 때. 억지로 한쪽으로 몰지 않기 위한 카테고리 |
| 판단불가 | 의미가 불분명한 짧은 표현 등 — 임의로 긍/부정/중립 채우지 않음 |
| 해당없음 | 실제 리뷰가 아닌 메타 기록(예: "수집 불가" 메모) |

별점만 있고 본문이 없는 경우 별점 기준으로 판정합니다: 4.5+=강한긍정, 4.0~4.4=약한긍정, 3.0~3.9=중립, 2.0~2.9=약한부정, 2.0미만=강한부정. `sentiment_basis` 컬럼에 "텍스트기준"/"별점기준"/"비리뷰"로 근거를 남깁니다.

R1(협찬 배제 — `협찬|제공받|원고료|체험단|서포터즈|소정의|증정`)에 해당하는 리뷰는 병합 데이터 기준 0건이었습니다.

## 날짜 정규화 (이슈 #68)

`approx_ym`(연-월 근사치)과 `date_precision`(정밀도: 일/월/년/없음)을 둡니다. `N년 전`처럼 월 정보가 없는 경우 `YYYY-미상`으로 표기하고 정밀도를 "년"으로 남깁니다 — 지어내지 않습니다. 병합 데이터 기준 594건 중 277건(47%)이 이 "년" 단위라, 월별 추이 그래프는 이 건들을 제외하고 그려야 합니다. 개별 수집 시각을 기록해두면(`collected_at`) 상대 날짜 변환 기준일이 명확해져 정확도가 올라갑니다.

다음 수집부터 병합 작업이 더 수월해지도록 정리한 최소 기준입니다 — 위 "수집 시 입력 항목"만 지켜주시면 나머지는 자동으로 처리됩니다.
